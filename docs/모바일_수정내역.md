# 모바일 웹 연동·UI 수정

일반 웹의 차량 시뮬레이터와 API를 기준으로 모바일 `/rider`를 수정했습니다. 원본 ZIP은 변경하지 않았습니다.

## 수정 내용

- **지도:** SDK 비동기 로딩, 현재 보이는 화면 초기화, 화면 크기 변경 감지, 탭 전환 시 지도 위치 유지, 배차·탑승 화면의 최신 차량 위치 복원, 지도 실패 안내와 재연결 버튼.
- **디자인:** 일반 웹과 동일한 네이비 헤더, ROBITA 브랜드, 회색 배경, 카드·버튼 형태와 상태 색상. 실시간 차량 현황과 지도 범례 추가. 320~480px 너비 대응.
- **호출:** 경유지 버튼의 누락된 span으로 인한 오류 해결, 중복 배차 차단, 결제수단·요청사항·인원 서버 반영. 배차 전에 결제 완료라고 표시하던 문구 수정.
- **경유:** 시뮬레이터가 경유지를 통과한 뒤 최종 목적지까지 이어서 운행. 앱을 닫아도 경유 처리가 진행되고 이용 건수는 한 번만 집계.
- **운행 복원:** 새로고침 시 탑승 여부·인원·결제수단·경유지·요청사항을 복구하고 배차 또는 운행 지도에 연결.
- **예약:** 화면에서만 완료 처리하던 예약을 서버 접수·취소·예약 시간 배차로 연결. 접수된 예약은 새로고침 후 확인 가능. 확정되지 않은 차량번호 대신 예약 대기 상태 표시.
- **이용내역:** 영수증의 결제수단과 모바일 이용내역 조회 연결. 일반 웹에서 호출의 실제 출발지/도착지를 기록. 원본의 누락된 `trips_today()`로 발생하던 `/api/trips` 오류 수정. 취소/고객 앱 호출 표시 보완.
- **경로 변경:** 서버에서 실제 경로 적용이 성공해야 변경 완료라고 표시. 길찾기가 연결되지 않으면 현재 경로 유지 안내.
- **실행:** Windows UTF-8 의존성 파일 처리, `START.cmd`, `.env.example`, 모바일 미리보기 추가.

## 실행

Windows에서 `START.cmd`를 실행하세요. 첫 실행은 Python 가상환경과 필요한 패키지를 설치하므로 인터넷 연결이 필요합니다.

- 모바일: http://127.0.0.1:8000/rider
- 모바일 화면 미리보기: http://127.0.0.1:8000/static/mobile-preview.html
- 일반 웹: http://127.0.0.1:8000/dashboard
- 기본 관리자: `admin@robotaxi.local` / `admin1234`

같은 Wi-Fi의 휴대폰에서는 `127.0.0.1` 대신 실행 PC의 LAN IP를 사용합니다. 해당 LAN 주소도 카카오 개발자센터의 웹 플랫폼 도메인에 등록되어 있어야 합니다.

## 검증

- 기존 로직 검사: 42개 통과.
- 추가 API·서비스 연동 검사: 12개 통과. 일반/모바일 차량·장소 일치, 예약 접수/취소/시간 배차, SUV, 경유 후 최종 이동, 중복 배차, 결제수단/영수증, 상담사 양방향 메시지 포함.
- 실제 Edge 모바일 브라우저 검사: 24개 통과, JavaScript 실행 오류 0개. 지도 타일, 320/360/430/480px, 호출/배차/탑승 지도, 새로고침 복구, WebSocket, 예약 접수/복구/취소, SDK 지연 및 실패 안내 검사.

추가 서버 테스트 실행:

```powershell
python -X utf8 -m pip install -r requirements-dev.txt
python -X utf8 test_logic.py
python -X utf8 -m unittest test_mobile -v
```

## 현재 실행 환경의 한계

- 원본에 카카오 길찾기 REST 키가 없습니다. 카카오 지도 배경과 실시간 차량 좌표는 표시되지만 실제 도로 경로·유료도로 회피를 확인하려면 `.env`에 `KAKAO_REST_KEY`를 설정해야 합니다. 키가 없는 차량 시뮬레이터는 경로 대기 후 좌표를 이동시키는 원본의 대체 동작을 사용합니다.
- LLM 키가 없어 AI 요청은 원본의 규칙 기반 모드로 실행했습니다.
- 예약·운행 세션·이용내역은 기존 서버와 같은 메모리 기반입니다. 브라우저 새로고침에서는 유지되지만 서버 종료/재시작 시 사라집니다. 예약 시각의 자동 배차에는 서버가 계속 실행되어 있어야 합니다.
- 실제 휴대폰 하드웨어에서는 검사하지 않았으며, Edge의 모바일 화면/터치 환경으로 검증했습니다.

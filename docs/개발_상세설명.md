## 2. 실행하기

### 준비물

- **Python 3.9 이상** (3.12 권장)
- 인터넷 연결 — 첫 실행 때 패키지 설치, 카카오 지도와 AI 호출에 필요합니다.
- (선택) OpenAI 또는 Gemini API 키, 카카오모빌리티 REST 키 — 없어도 실행됩니다.

### 방법 1. 윈도우에서 `START.cmd` 더블클릭

처음 실행하면 `.venv` 가상환경을 만들고 `requirements.txt`의 패키지를 설치한 뒤 서버를 켭니다.
두 번째부터는 바로 서버가 켜집니다.

### 방법 2. PyCharm

1. **File ▸ Open** 으로 프로젝트 폴더(`README.md`가 있는 폴더)를 엽니다.
2. `requirements.txt`를 열면 상단에 뜨는 **Install requirements** 를 누릅니다.
3. `run.py`를 열고 ▶(Run)을 누릅니다.

### 방법 3. 터미널

```bash
python -m venv .venv
.venv\Scripts\activate          # macOS / Linux: source .venv/bin/activate
pip install -r requirements.txt
python run.py
```

서버가 켜지면 터미널에 이 PC 주소(`http://127.0.0.1:8000`)와 휴대폰용 주소(`http://PC의IP:8000`)가
표시됩니다. 카카오 지도 도메인 등록과 맞추기 위해 **포트는 8000으로 고정**되어 있습니다.

### 접속 주소

| 화면 | 주소 | 로그인 |
|---|---|---|
| 관제 대시보드 | `/dashboard` | 필요 |
| 차량 모니터링 | `/monitor/RT-001` (차량 ID) | 필요 |
| 택시 호출 (운영자) | `/call` | 필요 |
| 금일 이용내역 | `/trips` | 필요 |
| 고객 앱 | `/rider` | 불필요 |
| 고객 앱 모바일 미리보기 | `/static/mobile-preview.html` | 불필요 |
| 데모 제어 | `/control` | 불필요 |
| 이벤트 관제 콘솔 | `/console` | 불필요 |
| 카카오맵 진단 | `/mapcheck` | 불필요 |

기본 관리자 계정은 `admin@robotaxi.local` / `admin1234` 이며, 회원가입으로 계정을 추가할 수 있습니다.
비밀번호는 pbkdf2로 해싱해 저장하고, 로그인은 세션 쿠키로 8시간 유지됩니다.

## 3. 설정 (`.env`)

`.env.example`을 같은 폴더에 `.env`로 복사한 뒤 필요한 값만 채웁니다.
(윈도우 PowerShell: `Copy-Item .env.example .env`) 값을 바꾼 뒤에는 서버를 다시 켜야 적용됩니다.

| 변수 | 설명 | 비워 두면 |
|---|---|---|
| `KAKAO_JS_KEY` | 카카오 지도 JavaScript 키 | 코드에 들어 있는 기본 키 사용 |
| `KAKAO_REST_KEY` | 카카오모빌리티 길찾기 키 ([developers.kakaomobility.com](https://developers.kakaomobility.com)) | 실제 도로 대신 직선·추정 경로 |
| `OPENAI_API_KEY` / `OPENAI_MODEL` | OpenAI 키와 모델 (예시 파일 기본값 `gpt-4.1-mini`) | Gemini 또는 규칙 기반 |
| `GEMINI_API_KEY` / `GEMINI_MODEL` | Gemini 키와 모델 (기본값 `gemini-2.5-flash`) | 규칙 기반 |
| `SECRET_KEY` | 세션 쿠키 서명용 비밀값 | 개발용 기본값 (배포 시 반드시 변경) |
| `FLEET_SIZE` | 승용 택시 대수 (SUV 3대는 별도로 추가) | 47 |
| `TICK_SECONDS` | 시뮬레이션 갱신 주기(초) | 2.0 |
| `DB_PATH` | 계정 DB 경로 | 프로젝트 폴더의 `robotaxi.db` |

AI 연결 상태는 화면 상단 배지로 확인합니다.

- `● ChatGPT 연결됨 (gpt-4.1-mini)` — OpenAI 사용 중
- `● Gemini 연결됨 (gemini-2.5-flash)` — Gemini 사용 중
- `● 규칙 기반 모드 (AI 키 미설정)` — 키 없이 규칙 기반으로 동작 중

> ⚠ `.env`에는 실제 키가 들어가므로 깃허브에 올리지 않습니다. `.gitignore`에 이미 등록되어 있습니다.

## 4. 화면별 기능

### 관제 대시보드 (`/dashboard`)

- **KPI** — 금일 운항 건수, 운행 수익, 등록 차량 수, 운행 차량 수 (전일 대비 증감)
- **운행 차량 현황** 도넛과 **시간대별 수요** 곡선
- **실시간 차량 지도** — 배터리 50% 이하는 노란 차량, 30% 이하는 빨간 차량으로 표시하고 SUV는 전용 아이콘을 씁니다.
  - 🚦 도로 혼잡도: 카카오맵 실시간 교통정보를 겹쳐 표시
  - 🔥 수요 히트맵: 현재 시간대의 수요 분포
  - 🚉 정왕역 / 🎓 한국공대 집중배치: 관리자가 대기 차량을 특정 지점으로 직접 보냄 (수동 개입)
- **🤖 AI 관제 브리핑** — 약 18초마다 운행 상황 요약, 이상 징후, 관리자 권고를 생성
- **💬 상담 요청** — 고객 앱에서 들어온 상담을 받아 관리자가 직접 채팅으로 응대 (Human-in-the-Loop)
- **🔔 알림** — 배터리 임계치, 사고·고장, 방전 이벤트

### 차량 모니터링 (`/monitor/{차량ID}`)

- 차량 상태, 배터리 잔량, 차량 컨디션 점수, 실시간 위치, 운행 기록
- **7개 에이전트 진행 로그** — 에이전트마다 입력 → 판단 → 실행 → 결과 4단계로 표시
- **에이전트 활동 이력** — 배차·사고 접수·견인·정비소 입고·충전 등 시간순 기록

### 택시 호출 (`/call`)

운영자가 출발지·목적지를 드롭다운이나 지도 클릭으로 지정해 호출합니다.
배차 에이전트가 차량을 고르고, 경로 모델이 추천 경로와 ETA를 지도에 그립니다.

### 금일 이용내역 (`/trips`)

총 이용 건수, 운행 수익, 평균 요금, 평균 평점, 수동 호출 수를 요약하고,
오늘의 운행·배차 기록을 표로 보여 줍니다. 4초마다 자동 갱신됩니다.

### 고객 앱 (`/rider`)

- **호출** — 출발지·도착지·경유지·탑승 인원(1~6명)·요청 사항·결제 수단을 정해 호출하거나, 챗봇에게 목적지를 말해서 호출
- **예약** — 원하는 시각을 정해 예약하면 그 시각에 배차 (취소 가능)
- **경로 선택** — 추천 경로와 무료도로 우선 경로 비교 (카카오모빌리티 키가 있을 때 실제 값)
- **실시간 추적** — 배차된 차량의 위치·경로·도착 예정 시간
- **탑승 중 요청** — "에어컨 켜 주세요", "정왕역 말고 시화병원으로" 같은 말을 AI가 이해해 실행
- **사고 대응** — 부상 확인 후 119 구급차 출동(시화병원 이송), 대체 차량 재배차
- **이용 후** — 영수증, 분실물 접수, 문의(AI 답변 또는 상담원 연결)
- **상담사 연결** — AI가 해결하지 못하는 요청은 관리자 대시보드의 상담 채팅으로 연결
- 요금은 기본 3,800원 + km당 1,300원 (최소 4,800원)이며, 5명 이상이면 SUV를 배차합니다.

### 데모 제어 (`/control`) · 이벤트 관제 콘솔 (`/console`)

발표·시연용 화면입니다. 서버 주소를 입력하면 휴대폰 등 다른 기기에서도 조작할 수 있습니다.

- **시간 제어** — ±30분·±1시간 이동, 실시간 / ×2 / ×4 / ×8 배속, 시간 고정
- **요일 지정** — 요일별 수요 패턴 재현 (`/control`)
- **이벤트 발생** — 사고, 배터리 방전 (`/console`은 고장, 충전시키기 추가)
- **수요 집중배치** — 정왕역·오이도역으로 대기 차량 집중 (`/control`)

## 5. AI 에이전트와 판단 방식

### 운영 에이전트 7종

| 에이전트 | 하는 일 | 판단 방식 |
|---|---|---|
| 재배치 | 시간대·요일별 수요 핫스팟 근처로 대기 차량을 미리 보냄 | 규칙 |
| 배차 | 호출마다 ETA 0.5 + 배터리 0.3 + 청결도 0.2 가중 점수로 차량 선택. 승객이 탄 차량·배터리 30% 미만·사고 차량은 후보에서 제외하고, 5명 이상이면 SUV만 고름 | 점수식 |
| 인시던트 대응 | 사고 접수 → 보험 접수 → 승객 안내 → 대체 차량 → 정비소 이동 → 기록 | 규칙 + LLM (절차 안내 문장) |
| 통합 관제 | 차량 위치·상태·배터리를 실시간으로 집계 | 규칙 |
| 정비 인텔리전스 | 센서·주행 데이터로 위험 점수·등급·조치 권고 산출 | LLM (실패 시 규칙) |
| 정비 오퍼레이션 | 정비가 필요하면 작업 지시, 대기 중 배터리 30% 이하이면 충전소로 이동 | 규칙 |
| 플릿 오케스트레이터 | 판단이 충돌하면 우선순위로 최종 실행안 하나를 확정 | 규칙 (정책 우선순위) |

플릿 오케스트레이터의 우선순위는 **인시던트 대응 → 정비 → 기존 배차 유지 → 충전 → 재배치** 입니다.
승객이 타고 있으면 배터리가 위험해도 목적지까지 운행을 마친 뒤 충전합니다. (`app/main.py`)

### 고객 응대 AI

| 기능 | 판단 방식 |
|---|---|
| 챗봇 호출의 목적지 이해 | 지점 이름 매칭 → 실패 시 LLM |
| 탑승 중 요청 (11개 기능 중 선택) | LLM → 실패 시 키워드 규칙 |
| 이용 후 문의 (답변 + 상담원 연결 필요 판단) | LLM → 실패 시 규칙 (분실물은 키워드로 바로 접수) |
| AI 관제 브리핑 | 지표·이상 징후는 규칙, 요약 문장은 LLM (실패 시 규칙 요약) |
| 경로 모델의 경로 사유 | 카카오 길찾기 또는 추정 거리 + LLM 사유 문장 (실패 시 규칙) |

LLM 호출이 실패하거나 응답이 늦으면(OpenAI 12초 제한) 같은 데이터로 규칙 기반 결과를 씁니다.
그래서 키가 없거나 네트워크가 불안정해도 기능이 멈추지 않습니다.
차량 모니터링 화면은 규칙 기반 로그를 먼저 보여 주고, LLM 결과는 백그라운드에서 받아 갱신합니다(차량별 60초 캐시).

## 6. 시뮬레이터 동작 규칙

| 항목 | 규칙 |
|---|---|
| 시각 | 기본은 실제 현재 시각(한국 시간). 데모 제어에서 시각 이동·배속·고정·요일 지정 가능 |
| 운행 비율 | 수요에 따라 운행 차량 비율을 12%(심야) ~ 82%(러시아워)로 조절 |
| 배터리 | 50% 이하 '주의', 30% 이하 '위험'. 대기 중 30% 이하가 되면 가까운 충전소로 이동 |
| 재배치 | 25틱(약 50초)마다 실행. 대기 차량의 60%를 시간대 핫스팟에 나눠 두는 것을 목표로, 가장 부족한 핫스팟 한 곳에 가까운 대기 차량을 최대 3대 보냄. 다른 핫스팟 반경(0.9km) 안에 있는 차량은 빼 오지 않음 |
| 사고·고장 | 견인차가 정비센터로 이동, 부상자가 있으면 119 구급차가 시화병원으로 이송 |
| 경로 | 카카오모빌리티 키가 있으면 실제 도로 경로, 없으면 직선 경로 |

## 7. 휴대폰으로 시연하기

1. PC와 휴대폰을 **같은 와이파이나 핫스팟**에 연결합니다.
2. 서버를 켜고 터미널에 표시된 `http://PC의IP:8000` 주소를 확인합니다.
3. 그 주소를 카카오 개발자센터에 등록합니다.
   [developers.kakao.com](https://developers.kakao.com) → 앱 선택 →
   **[앱] > [플랫폼 키] > [JavaScript 키] > [JavaScript SDK 도메인]**에 `http://PC의IP:8000`을 추가합니다.
   `http://`와 `:8000`까지 똑같이 적어야 합니다. PC용 `http://localhost:8000`과 `http://127.0.0.1:8000`도 함께 등록해 둡니다.
4. 휴대폰에서 `http://PC의IP:8000/rider`를 엽니다.
5. 지도가 안 뜨면 휴대폰에서 `http://PC의IP:8000/mapcheck`를 열어 원인을 확인합니다.

> 핫스팟은 껐다 켜거나 다시 연결하면 PC의 IP가 바뀔 수 있습니다. 발표 현장에서는 연결 → 주소 확인 →
> 등록 → `/mapcheck` 확인까지 마친 뒤 핫스팟을 끄지 않는 것이 안전합니다.

## 8. 테스트와 평가

```bash
python test_logic.py                    # 핵심 로직 42개 → "결과: 42 통과 / 0 실패"
pip install -r requirements-dev.txt     # 아래 테스트용 패키지(httpx)
python -m unittest test_mobile -v       # 고객 앱·API 연동 12개
python evaluation/robita_eval.py        # 성능 평가 (키 필요 없음, 약 3분)
python evaluation/eval_llm.py           # 고객 AI 판단 정확도 (LLM 키 필요)
```

`test_logic.py`는 임시 DB를 쓰므로 실제 `robotaxi.db`를 건드리지 않습니다.
평가 방법과 결과는 [evaluation/README.md](../evaluation/README.md)에 정리되어 있습니다.

## 10. 자주 묻는 문제

- **지도가 안 떠요 / "지도를 불러오지 못했어요"가 나와요**
  → 대부분 접속한 주소가 카카오에 등록되지 않은 경우입니다. 7장의 3번처럼 주소를 등록하고,
  `/mapcheck`에서 'SDK 스크립트 로드'가 성공으로 바뀌는지 확인하세요. 광고 차단 확장 프로그램도 원인이 될 수 있습니다.
- **휴대폰에서 페이지 자체가 안 열려요**
  → PC와 같은 네트워크인지, 주소의 IP가 맞는지 확인하세요. 윈도우 방화벽 창이 떴다면 Python 접근을 허용해야 합니다.
- **상단에 '규칙 기반 모드'가 떠요**
  → `.env`가 프로젝트 폴더(`run.py`와 같은 위치)에 있는지, 키가 맞는지 확인하고 서버를 다시 켜세요.
- **차량이 직선으로 움직여요**
  → `KAKAO_REST_KEY`가 없으면 직선 경로로 동작합니다. 실제 도로 경로를 보려면 키를 넣으세요.
- **`ModuleNotFoundError`가 나요**
  → 가상환경을 켠 상태에서 `pip install -r requirements.txt`를 다시 실행하세요.
- **설치 중 `Rust`, `cargo`, `building wheel` 같은 오류가 나요**
  → 너무 최신인 파이썬에서 일부 패키지가 아직 준비되지 않은 경우입니다. Python 3.12로 가상환경을 만들어 설치하세요.
- **포트 8000이 이미 사용 중이에요**
  → 이미 켜진 서버를 끄세요. 포트를 바꾸면 카카오에 바뀐 주소도 등록해야 합니다.
- **서버를 다시 켰더니 이용내역·예약·상담 기록이 사라졌어요**
  → 계정 외의 기록은 메모리에 두는 구조라 정상입니다.
- **관리자 비밀번호를 잊었어요**
  → 서버를 끄고 `robotaxi.db`를 지운 뒤 다시 켜면 기본 관리자 계정만 있는 상태로 초기화됩니다.

## 11. 참고

- 수행계획서의 PostgreSQL·Redis·Kafka 대신, 한 대의 PC에서 바로 실행되도록 SQLite + 메모리 시뮬레이션 + WebSocket으로 단순화했습니다.
- 고객 앱, 데모 제어, 이벤트 관제 콘솔, 지도 진단 화면은 시연 편의를 위해 로그인 없이 열립니다.
  외부에 공개 배포할 때는 이 화면들의 접근을 막고, `SECRET_KEY`를 긴 임의 값으로 바꾸고, DB를 운영용으로 교체해야 합니다.
- 시뮬레이터의 수요·사고는 실제 데이터가 아닌 시간대별 패턴과 확률로 생성됩니다.

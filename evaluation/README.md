# 평가 (논문 2.4 시스템 동작 및 평가)

실제 `app/` 코드를 그대로 불러와 플릿 시뮬레이터에서 측정합니다.
측정 조건은 차량 50대(세단 47 + SUV 3), 2초 주기, 시간대 고정(수요일), 격자형(L자) 도로 경로 근사,
난수 시드 20개 반복입니다.

## 실행

| 측정 | 명령 (프로젝트 폴더에서) | 시간 | API 키 |
|---|---|---|---|
| 시뮬레이션 평가 (E1~E5) | `python evaluation/robita_eval.py` | 약 3분 | 필요 없음 |
| 고객 AI 판단 정확도 (LLM) | `python evaluation/eval_llm.py` | 약 5분 | `.env`의 OpenAI 키 |

결과는 `evaluation/result.json`, `evaluation/eval_llm_result.json` 으로 저장됩니다.

## 결과 (`result_fixed.json`)

| 항목 | 방법 | 결과 |
|---|---|---|
| 재배치 효과 | 대기 차량이 수요 집중 지점 밖에 몰린 상황 20회, 재배치 적용/미적용 30분 비교 | 대기 차량 부족률 66.9% → 45.6% (31.8% 감소), 예상 픽업 시간 2.86분 → 2.29분 (19.7% 단축), 20회 모두 개선 |
| 충돌 조정 | 충돌 상황 9종 × 20회 | 오케스트레이터 판단과 실제 동작이 정책 우선순위와 일치 180/180 |
| 운영 시나리오 | 정상 호출 400건, 수요 불균형·배터리 부족·사고 각 40회 | 기대 조치 수행 100% |
| 배차 | 호출 2,820건, 최근접 배차와 비교 | 픽업 시간 +0.3분, 배정 차량 평균 배터리 65.7% → 86.5% |
| 고객 AI (키워드 규칙) | 탑승 중 요청 48건 / 이용 후 문의 24건 | 56.2% / 58.3% (LLM 결과는 `eval_llm.py`로 측정) |

`result_before_fix.json` 은 배차 후보·오케스트레이터 우선순위·재배치를 고치기 전 코드로 측정한 결과입니다.
신규 호출의 49.2%가 승객이 탄 차량에 배정되었고, 충돌 조정은 판단 77.8%·동작 88.9%만 정책과 일치했습니다.

## 한계

- 시뮬레이터의 호출 위치는 실제 수요 분포를 반영하지 않으므로, 재배치 효과는 수요 예측 지점 기준 지표(대기 차량 부족률, 예상 픽업 시간)로 측정했습니다.
- 수요와 공급이 이미 균형인 평상시에는 재배치 효과가 미미했습니다(4개 시간대 평균 부족률 1.0% 감소).
- 도로는 격자형 경로로 근사했고 교통 혼잡은 반영하지 않았습니다.
